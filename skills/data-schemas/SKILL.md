# Data schemas

The code is the source of truth. This skill summarizes it and names the module that enforces each
schema. All paths are relative to the repository root.

## 1. Hydrograph store (`<root>/hydrographs/<leaderboard_id>/<model_id>.zarr`)

Enforced by `models/zarr_writer.py` (`build_hydrograph_dataset`, `validate_hydrograph_dataset`,
`write_hydrograph_zarr`). The human version is in `models/README.md`, section "Zarr Hydrograph
Output".

| Item | Specification |
| :--- | :--- |
| Format | Consolidated Zarr v2. `qsim` is one chunk; `qsim_members` is one chunk per member. |
| Dimensions | `basin` = 531, `date` = 3,652; plus `member` = N for ensembles |
| Coordinates | `basin` (`<U8`, sorted canonical IDs); `date` (`datetime64[ns]`, `1989-10-01`..`1999-09-30`); `huc_02` (`<U2` on `basin`); `member` (`int64`) |
| `qsim` | `float32`, mm/day, `(basin, date)`, finite everywhere |
| `qsim_members` | optional `float32` `(member, basin, date)`. For an ensemble, `qsim` must equal the member mean (tolerance 1e-4). |
| Required attributes | `entry_id`, `model_name`, `family_id`, `provenance_category`, `leaderboard_id`, `spatial_regime` (`gauged`/`pub`/`pur`), `forcing_regime`, `forcings_used`, `is_ensemble`, `num_members`, `train_period`, `test_period` (`A/B`), `units`, `code_url` (non-empty), `archive_url` |
| Extra attributes | `model_id`, `model_family`, `table_id`, `spatial_protocol` (`gauged`/`pub_12fold`/`pur_18huc02`), `forcing_products`, `training_period`, `evaluation_period`, `data_url`, plus run provenance from `run_model.py` (`seeds`, `fold_ids`, `runner_kwargs_json`, `git_commit`, `git_dirty`, `created_utc`, `data_source`, which holds a file name only) |

Store and entry IDs must match `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$` and must not contain `..`.

## 2. Observation targets (`<root>/observations/newman_eval_targets.zarr`)

Built by `metrics/build_eval_targets.py` from the raw NCAR CAMELS-US v1.2 files and checked by the
evaluator.

| Name | Dims | Content |
| :--- | :--- | :--- |
| `basin`, `huc_02` | `(basin,)` 531 | sorted IDs; 2-digit region codes |
| `date` | `(date,)` 3,652 | `1989-10-01`..`1999-09-30` |
| `date_all` | `(date_all,)` | `1980-01-01`..`2008-12-31` |
| `qobs` | `(basin, date)` | observed mm/day; missing values are NaN |
| `qobs_all` | `(basin, date_all)` | observed mm/day over the full record |
| `newman_train_mask`, `newman_test_mask` | `(date_all,)` | boolean training and evaluation windows |

## 3. Split files (`mips/camels_us_daily/splits/`)

- `basins_531.txt` / `.json`: the sorted canonical IDs. `basins_671.*` and
  `basins_447_kratzert2019b.*` are reference lists.
- `pub_12fold_random_splits.json` and `pur_18fold_huc02_splits.json`: top-level `folds`. Each fold
  (`fold_00`.., `huc_01`..) has `fold_index`, `n_train`, `n_test`, `train_basins`, `test_basins`,
  `train_indices`, and `test_indices` (PUR folds also have `huc_02`). Plain-text copies are in
  `pub_12fold/` and `pur_18fold/`.
- `splits_and_regimes.json`: the protocol summary, including `basin_to_huc02`.
- Load folds with `models.run_model` (for runs) or `mips.camels_us_daily.adapter` (for checks).
  Never read them inside model code.

## 4. Leaderboard JSON (`mips/<mip_id>/leaderboards/<leaderboard_id>.json`)

Generated by `leaderboards/update_leaderboard.py`. Never edit by hand.

- Top-level fields: `id`, `table_number`, `section`, `spatial_regime`, `forcing_regime`, `title`,
  `short_title`, `tab_label`, `subtitle`, `n_entries`, `top_model`, `top_nse`, `rows`, `protocol`.
- Row fields, by group:
  - **Identity:** `entry_id`, `leaderboard_id`, `model_name`, `family_id`, `family_name`,
    `paradigm`, `model_category`.
  - **Provenance:** `category`, `code_provenance`, `citation`, `paper_url`, `publication_year`,
    `code_url`, `github_url`, `data_archive_url`, `zenodo_doi`, `zenodo_url`.
  - **Inputs and ensemble:** `forcing`, `is_ensemble`, `num_members`, `has_qsim_members`.
  - **Scores:** `ens_med_nse`, `single_med_nse`, `single_med_nse_std`, the `*_display` strings,
    `primary_ranking_nse` (the ranking key), `mean_nse`, `med_kge`, `med_fhv_abs`, `nse_le_0`,
    `num_evaluated_basins`, `rank`, and for store-backed rows `pred_nan_when_obs_valid`.
  - **Detail:** `gauch_2023_metrics` (the 14 metrics, in the order of
    `GAUCH_2023_DETERMINISTIC_SUITE.metric_names`, each with `median`, `mean`, `min`,
    `p01`..`max`), `regional_huc02` (by region code), `per_basin_nse` (531 values or `null`).
  - **Store and flags:** `zarr_path` (for store-backed rows), `asterisk` and `asterisk_reason`.
- `tables_3_to_14.json` combines all 12 files (`protocol`, `total_entries`, `leaderboards`). It is
  regenerated by `leaderboards/on_community_commit.sh`.
- Displayed tables (website and paper) show 16 summary columns per row: the 531-basin median of
  each of the 14 metrics (from `gauch_2023_metrics`), plus mean NSE and mean KGE.

## 5. Registries

- `table_2_registry.json`: `total_families`, `num_families`, `n_families`, and `families[]` with
  `family_id`, `name`, `category`, `model_category`, `provenance_category`, `paradigm`, `citation`,
  `paper_url`, `github_url`, `code_dir`, `zenodo_doi`, `zenodo_url`, `hydroshare_url`,
  `description`, `asterisk`, `asterisk_reason`, `n_entries`, `leaderboards_covered`, `best_nse`,
  `year`.
- `contributions_index.json`: `total_contributions` and `entries` keyed by entry ID, with
  `entry_id`, `leaderboard_id`, `model_name`, `family_id`, `category`, `code_provenance`,
  `spatial_regime`, `forcing_regime`, `forcings_used`, `is_ensemble`, `num_members`,
  `has_qsim_members`, `ensemble_source`, `metrics`, `hydrograph_path`, `code_url`, `data_url`,
  `target_leaderboard_tables`, `gauch_2023_metrics`.
- `models/catalog.json`: `schema_version` (`hydromip-model-catalog-v1`) and `models[]` with `key`,
  `model_name`, `model_family`, `provenance_category`, `runner_module`, `code_url`,
  `supported_tasks`, `supported_mips`, `supported_forcing_regimes`, `supported_spatial_regimes`. It
  mirrors `MODEL_REGISTRY`.

## 6. `protocol.json`

Schema version `hydromip-protocol-v1`, validated by `hydromip/protocol.py`. Required keys and rules
are in `hydromip/README.md` and `skills/contribute-mip/SKILL.md`.

## 7. Evaluator output (`mip-score-model --output-json`)

`metrics.evaluator.calculate_model_leaderboard_metrics` returns:

- `model_id`, `leaderboard_id`, `bucket_uri`, `hydrograph_uri`, `targets_uri`;
- `summary`, which contains:
  - `num_total_basins`, `num_evaluated_basins`, `num_eval_days`, `pred_nan_when_obs_valid`;
  - the ensemble fields: `is_ensemble`, `num_members`, `single_seed_median_nse_mean`, `..._std`,
    `..._per_member`;
  - the headline metrics: `median_nse`, `mean_nse`, `median_kge`, `median_abs_fhv`,
    `nse_le_zero_count`;
  - medians and quartiles of the other metrics, for example `median_log_nse` and `median_log_kge`;
  - percentiles and HUC-02 summaries;
  - `gauch_2023_metrics` (all 14 metrics);
- `regional_huc02`, `per_basin`, and the store `attributes`.

The summary keys are also copied to the top level.

## 8. Portal scoring uploads (`/api/score` on https://hydrologymip.org)

The portal accepts a zipped Zarr store (`.zarr.zip` or `.zip`) that follows section 1, or a keyed
`.npz` with `qsim` `(531, 3652)`, `basin`, and `date` (optionally `qsim_members`). Bare `.npy`
files are rejected because they have no coordinates.
